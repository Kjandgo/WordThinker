# 프론트엔드 코딩 에이전트 하네스

## 시작

저장소 루트 `D:\myWorkSpace\enword`를 작업 디렉토리로 열고 작업을 요청한다. 루트 `AGENTS.md`가 기본 역할을 프론트엔드 담당으로 지정하고, `wordthinker-fe/AGENTS.md`로 세부 개발 규칙을 연결한다. 프론트 폴더에서 시작하는 경우에도 두 지침을 함께 따른다.

요청 예시:

> 단어장 검색 UI를 개선해 줘. 모바일에서도 사용하기 쉽게 만들고 기존 검색·필터와 저장 동작을 확인해 줘.

추가 에이전트 프로세스나 API 키 없이 저장소 지침으로 사용하는 구성이다. 파일 접근을 강제로 제한하려면 실행 환경에서 별도 권한 설정이 필요하다.

## 담당과 경계

| 경로 | 기본 책임 |
| --- | --- |

## 검증과 완료 기준

명령은 `wordthinker-fe/`에서 실행한다. Node 버전은 `package.json`의 `engines`를 따른다.

```powershell
Set-Location D:\myWorkSpace\enword\wordthinker-fe
npm install
npm run dev
```

의존성 설치는 처음 실행하거나 의존성이 변경된 경우에 수행한다. 개발 서버는 UI 확인에 필요할 때 실행한다.

- 문서 변경: 링크, 경로, 명령과 지침의 일관성을 확인한다.
- 앱 코드 또는 빌드 설정 변경: `npm run build`를 실행한다.
- AI 서비스 또는 승인된 n8n 워크플로우 변경: `node scripts/check-ai-workflow.mjs`를 실행한다. 실제 AI 요청은 포함하지 않는다.
- UI 변경: 변경한 사용자 흐름, 관련 오류·빈 상태·로딩 상태, 모바일 화면과 키보드 조작을 확인한다.
- 라우트·저장·AI 기능별 추가 점검은 `wordthinker-fe/AGENTS.md`를 따른다.

JavaScript·Vue 코드 또는 ESLint 설정 변경 시 `npm run lint`를 실행한다. 자동 수정은 `npm run lint:fix`를 사용한다. 현재 `test` npm 스크립트는 없다. 검증을 실행할 수 없으면 이유와 미확인 범위를 보고한다. API 미구현 상태에서 UI만 완성했다면 연동 대기 상태임을 명시한다.

## 백엔드 인계 양식

백엔드 의존성이 생겼을 때만 `docs/` 아래에 작업별 문서를 작성한다. 확인된 계약과 제안을 구분하고, 비밀값이나 실제 사용자 데이터를 넣지 않는다.

```markdown
# <기능명> API 연동 인계

- 화면에서 어떤 동작을 제공해야 하는가:

## 확인된 계약
- 근거 파일 또는 문서:
- HTTP 메서드와 경로:
- 요청·응답 형식:
- 인증·오류 처리:

## 백엔드에 필요한 변경 또는 확인
- 아직 확정되지 않은 항목과 제안:
- 호환성 요구사항:

## 프론트엔드 진행 상태
- 구현한 내용:
- 실제 수행한 검증과 결과:
- 연동 후 남은 확인:
```

## 결과 보고

최종 보고에는 변경한 동작, 실제 검증 결과, 남은 API 의존성이나 미확인 사항을 포함한다. 이 하네스 자체를 바꾸는 작업에서는 앱 코드를 변경하지 않았다면 앱 빌드를 실행할 필요가 없다.

## 컨텍스트 GC

작업 맥락의 보존·정리·복원 절차는 [컨텍스트 GC](context/README.md)를 따른다. 시작할 때 [현재 체크포인트](context/current.md)를 읽고 실제 Git 상태와 대조한다. 종료·전환하거나 조사 기록이 길어지면 핵심 상태만 체크포인트에 남긴다. 완료 이력은 필요할 때만 `context/archive/`에서 읽는다.
