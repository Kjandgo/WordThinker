# 컨텍스트 GC

긴 대화와 조사 결과를 다음 작업에 필요한 상태로 압축하는 저장소 기반 절차다. 에이전트가 문서를 읽고 갱신하며, 모델의 컨텍스트 창이나 대화 기록을 자동으로 삭제하는 기능은 아니다.

## 구조

- `current.md`: 현재 목표, 제약, 진행 상태, 검증 결과, 다음 행동을 담는 단일 체크포인트.
- `archive/`: 완료 또는 중단한 작업 중 다시 참고할 가치가 있는 기록. 필요할 때만 읽는다.
- `../frontend-harness.md`: 실행·검증 방법과 백엔드 인계 양식. 체크포인트에는 이 내용을 복사하지 않고 링크한다.

## 시작과 복원

1. 루트와 프론트 `AGENTS.md`, 이 문서, `current.md`를 읽는다.
2. `git status --short` 및 관련 코드와 문서를 확인한다. 체크포인트는 참고 자료이며 현재 사용자 지시와 실제 저장소 상태가 우선한다.
3. 체크포인트의 작업이 현재 요청과 다르면 자동으로 재개하지 않는다. 관련 제약과 미완료 사항만 참고하고 현재 목표를 갱신한다.
4. 필요한 파일만 읽는다. 아카이브 전체나 이전 로그를 일괄 로드하지 않는다.

## GC 시점

- 작업을 마치고 최종 보고하기 전.
- 다른 목표로 전환하거나 인계할 때.
- 조사·오류 로그가 길어져 핵심 상태를 파악하기 어려워졌을 때.
- 세션 종료나 컨텍스트 압축을 예상할 수 있을 때. 예고 없이 끊긴 세션은 마지막 체크포인트 이후 상태를 Git과 파일에서 다시 확인한다.

## GC 절차

1. 사용자 목표, 완료 조건, 최신 제약을 확인한다. 진행 중 사용자가 수정한 요구사항을 반영한다.
2. 완료·진행 중·대기 항목을 구분한다. 검증은 실행 명령, 결과, 미확인 범위를 기록한다.
3. 파일 경로와 결정 이유를 남기고, 소스 전체·명령 출력·반복 설명·폐기한 추측은 체크포인트에서 제거한다. 중요한 실패 원인과 재시도 조건은 유지한다.
4. 이전 목표의 기록을 보존해야 한다면 먼저 `archive/YYYY-MM-DD-주제.md`에 필요한 내용만 옮긴다. 같은 이름이 있으면 덮어쓰지 않고 접미사를 붙인다. `current.md`에는 필요한 아카이브 링크만 남긴다.
5. `current.md`를 최신 상태로 덮어 쓴다. 본문은 약 100줄 이내를 목표로 하되 미완료 요구사항, 차단 요인, 기존 변경 보존 정보를 분량 때문에 누락하지 않는다.
6. 경로·링크가 유효한지, 미실행 검증을 성공으로 기록하지 않았는지 확인한다.

GC는 문서의 중복 정보를 정리한다. 작업 파일, 사용자 데이터, Git 변경, 아카이브를 자동 삭제하지 않는다. 비밀값과 실제 사용자 데이터는 기록하지 않는다. 영구 규칙은 `AGENTS.md`, 상세 계약은 해당 인계 문서에 두고 체크포인트에는 링크한다.

- 상태: 진행 중 / 대기 / 완료

## 진행과 결정
- 완료한 내용, 관련 파일, 중요한 결정 이유:

## 검증
- 실제 실행한 명령과 결과:
- 미실행 항목과 이유:

## 남은 작업과 다음 행동
- 미완료 요구사항, 차단 요인, 바로 이어서 할 행동:

## 참고
- 관련 문서 또는 필요한 아카이브 링크:
